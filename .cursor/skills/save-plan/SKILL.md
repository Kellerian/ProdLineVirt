# Save Plan

Сохрани **готовый** план разработки в репозиторий. Это **не** планирование с нуля — для исследования кода и декомпозиции через субагент `planner` используй `plan-development` (`/plan`, `/create-plan`).

## Когда применять

- Пользователь вызвал `/save-plan` или просит сохранить план в `.plans/backlog/`.
- В чате уже есть согласованный план (включая вывод Plan mode / CreatePlan).
- Нужно обновить **существующий** файл в `.plans/` без запуска planner.

## Источник плана (по приоритету)

1. Явный путь от пользователя (файл плана, `@`-ссылка).
2. Последний артефакт Plan mode: `~/.cursor/plans/*.plan.md` (или путь из контекста сессии).
3. Текст плана в текущем чате (последнее сообщение ассистента с подзадачами / чеклистом).

Если источник неоднозначен — уточни у пользователя один раз; не выдумывай подзадачи.

## Куда писать

| Ситуация | Каталог | `status` в frontmatter |
|----------|---------|-------------------------|
| Новый план, готов к выполнению | `.plans/backlog/` | `backlog` (по умолчанию) |
| Черновик, ещё правят | `.plans/backlog/` | `draft` (если пользователь просит черновик) |
| Обновление существующего | тот же файл | сохрани текущий `status`, обнови `updated` |

Создай `.plans/backlog/`, `.plans/in_progress/` и др. при отсутствии.

**Не** переноси в `in_progress/` — это делает `/execute-plan` при старте.

## Имя файла

```text
.plans/backlog/YYYY-MM-DD-<kebab-slug>.md
```

- Дата: сегодня (локальная) или `created` из исходника.
- Slug: из `title` (латиница/транслит, kebab-case), 3–6 слов.
- Если файл уже существует и пользователь не просил перезапись — спроси или добавь суффикс `-2`.

## Формат (обязательный)

Сверься с образцами в `.plans/complete/*.md` и завершёнными планами в `.plans/backlog/`.

### Frontmatter

```yaml
---
title: <краткое название>
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: backlog   # или draft
priority: low | medium | high
estimated_subtasks: <N>
---
```

### Тело

- `#` заголовок = `title`
- **Контекст и цель** — проблема, успех, ограничения
- При необходимости: диаграммы, таблицы, «Что не трогаем», риски
- **Подзадачи** — секции `### N. …` с полями:
  - **ID**, **Стек** (`backend` | `frontend` — для Line Emulator чаще `backend`/PySide6)
  - **Описание**, **Файлы/модули**, **Критерии готовности**, **Зависимости**, **Оценка** (S/M/L)
  - В конце каждой подзадачи: `- [ ] Выполнено`
- В конце плана — подсказка для запуска (опционально):

  ```text
  /execute-plan .plans/backlog/YYYY-MM-DD-<slug>.md
  ```

Перенеси содержание из источника **без потери** решений из grilling/чата; не сокращай критерии готовности.

## Жёсткие правила

- **Не** пиши продуктовый код и **не** запускай `developer` / `execute-plan`.
- **Не** вызывай субагент `planner` (это `plan-development`).
- **Не** меняй `VERSION`, `CHANGES.LOG`, тесты — только файл плана (и при необходимости mkdir под `.plans/`).
- Один вызов skill → один целевой `.md` (или явное обновление указанного файла).

## После сохранения

Ответ пользователю:

- полный путь к файлу;
- число подзадач и `status`;
- одна строка: запуск через `/execute-plan <путь>` или Build в Plan mode по `plan-execution-orchestration`.
