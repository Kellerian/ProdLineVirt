# Plan Development

Используй этот skill, когда пользователь просит `/plan`, `/create-plan`, планирование разработки, декомпозицию задачи или roadmap.

Запусти ровно один субагент `planner` с:

- `readonly: true`
- `run_in_background: false`, если пользователь явно не просит фоновый запуск
- `description: "Development Planner"`
- `subagent_type: "planner"`

Используй корень активного workspace как `Full Repository Path`.

Форма промпта:

```text
Full Repository Path: <абсолютный путь к репозиторию>
Task: <полное описание задачи пользователя>
Context: <дополнительный контекст из чата, если есть>
Constraints: <ограничения: сроки, не трогать X, только backend и т.д. — если указаны>
Existing Plan: <путь к .plans/*.md, если нужно обновить существующий план>
Custom Instructions: <только если пользователь дал особые инструкции по формату или scope>
```

Субагент сам исследует кодовую базу и сохраняет **новый** план в `.plans/backlog/` (`status: draft`). Перенос в `.plans/in_progress/` при старте выполнения, в `.plans/complete/` при завершении и в `.plans/cancelled/` при отмене — задача оркестратора или planner (при фиксации `status: cancelled`). Не пиши план вместо субагента и не реализуй код до завершения планирования (если пользователь явно не попросил и то, и другое).

Если субагент завершился с ошибкой:

- Исправь некорректный вызов (путь, форма промпта) и повтори один раз.
- При других сбоях — один повтор с тем же промптом.
- Если снова неудача — кратко сообщи о блокере.

После завершения субагента:

- Верни путь к файлу плана и краткое резюме (число подзадач, первый шаг).
- Предложи запустить `developer` для реализации первой подзадачи только если уместно; не навязывай.

Обновление чеклиста: при выполнении подзадач в основной сессии отмечай `- [x]` в файле плана (обычно `.plans/in_progress/`) и обновляй `status` / `updated` в frontmatter.
