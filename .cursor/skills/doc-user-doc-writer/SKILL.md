# Doc User Doc Writer

Используй этот skill, когда пользователь просит `/user-doc`, `/whatsnew`, пользовательскую документацию, инструкции для операторов или обновление `WHATSNEW.md`.

Запусти ровно один субагент `user-doc-writer` с:

- `readonly: false` — субагент создаёт и правит файлы документации
- `run_in_background: false`, если пользователь явно не просит фоновый запуск
- `description: "User Doc Writer"`
- `subagent_type: "user-doc-writer"`

Используй корень активного workspace как `Full Repository Path`.

Форма промпта:

```text
Full Repository Path: <абсолютный путь к репозиторию>
Task: <что задокументировать: фича, исправление, экран, приложение, завершённый план>
Scope: <одно из: "user-guides", "whatsnew", "user-guides+whatsnew", "plan-completion">
Context: <контекст из чата: что сделано, затронутые экраны/UI, версия>
Target Docs: <пути docs/<app>/user-guides/... — если известно>
Plan File: <путь к .plans/*.md — при завершении плана>
Source Changes: <одно из: "git diff", "uncommitted changes", "described in chat">
Custom Instructions: <особые требования; по умолчанию — простой язык, без технических деталей>
```

- По умолчанию `Scope`: `user-guides+whatsnew`, если затронут пользовательский опыт.
- Только «Что нового» — `Scope: whatsnew`.
- В конце execute-plan оркестратор вызывает с `Scope: plan-completion` (см. `execute-development-cycle`).

Субагент сам исследует код UI и существующую документацию. Не пиши пользовательскую документацию вместо субагента.

Если субагент завершился с ошибкой:

- Исправь некорректный вызов (путь, форма промпта) и повтори один раз.
- При других сбоях — один повтор с тем же промптом.
- Если снова неудача — кратко сообщи о блокере.

После завершения субагента:

- Верни список изменённых `user-guides/` и статус `WHATSNEW.md`.
- Если остались пробелы — перечисли их кратко.

Не вноси правки в прикладной код и `CHANGES.LOG`, если пользователь явно не попросил.
