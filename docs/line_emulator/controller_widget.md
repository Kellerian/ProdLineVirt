# Виджет контроллера (`ControllerWidget`)

| Параметр | Значение |
|----------|----------|
| Версия проекта | `client_info.VERSION` (актуально `1.0.0.1.b0013`) |
| Код | `core/controller/controller_widget.py` |
| UI | `forms/ui/Controller.ui` (класс формы `Form` → `forms/Controller.py` через `pyuic`) |
| Контекст | эмулятор линии — см. [line_emulator.md](line_emulator.md), ядро — [controller_core.md](controller_core.md) |

Qt-виджет карточки **Modbus/Doypack** на холсте Line Emulator: поля конфигурации, кнопка **Run/Stop**, таблица наблюдаемых **holding** и **coil**, удаление. Документ описывает привязку UI к коду и рантайму; **пользовательских сценариев** здесь нет.

Карточка создаётся из `MainLineField` и участвует в сохранении/загрузке линии вместе с остальными виджетами (`options()` / `load_options()`).

## Макет карточки

- Фиксированная ширина карточки (**260** px): верхний ряд блоков (имя, порт, R/S, X) и ниже — поля очереди, режима и типа ПЛК.
- У `spQueueSize`, `cbMode` и `cbType` вертикальная политика размера **Fixed** — строки «Размер очереди», «Режим», «Тип» занимают ровно свою высоту и не растягивают карточку по вертикали «пустотой».
- Под ними на всю ширину: кнопка **«Добавить переменную»** (`btnAddRegister`) и таблица `tblRegisters` с **растяжением** по вертикали в колонке макета (stretch **1**), минимальная высота таблицы **120** px, вертикальная прокрутка по необходимости.
- Ограничение прежней фиксированной высоты карточки (**220** px) снято: высота определяется содержимым и растягиванием таблицы.

## Поля формы (`Controller.ui`)

Элементы именованы как в сгенерированном `Ui_Form` (`forms/Controller.py`).

| Элемент | Тип | Назначение |
|---------|-----|------------|
| `leName` | `QLineEdit` | Имя устройства на карточке; `maxLength` 25, плейсхолдер «Название устройства». |
| `lePort` | `QLineEdit` | TCP-порт прослушивания Modbus (текст; парсинг `int` при запуске и в `options()`). |
| `spQueueSize` | `QSpinBox` | Размер очереди Doypack: **1…1000** (по умолчанию 10), см. `ControllerConfig.queue_size`. |
| `cbMode` | `QComboBox` | Режим линии: **Simplex** → `ControllerMode.simplex`, **Duplex** → `ControllerMode.duplex` (тултип «Режим линии Doypack»). |
| `cbType` | `QComboBox` | Тип ПЛК / карта регистров: **Delta** → `ControllerType.delta`, **Xinje** → `ControllerType.xinje` (тултип «Карта регистров ПЛК»). |
| `tbRun` | `QToolButton` | Переключаемая кнопка **Run/Stop** (см. ниже). |
| `tbDelete` | `QToolButton` | Удаление карточки («X», тултип «Удалить»). |
| `btnAddRegister` | `QPushButton` | Текст **«Добавить переменную»** — добавляет в конец таблицы новую строку с пустым адресом. |
| `tblRegisters` | `QTableWidget` | Две колонки: **«Переменная»** (токен адреса holding или coil, **всегда редактируемый**, в т.ч. при **S**) и **«Значение»** (при **R** — только чтение; при **S** — **редактируемый**, ввод с клавиатуры и двойным щелчком; при опросе и после записи — цвет текста). Номера строк включены; **toolTip** таблицы кратко описывает синтаксис `D`/`M` и голых чисел (полный контракт — [config_controllers.md](config_controllers.md)); типовые старты очереди Doypack — в [controller.md](controller.md). |

При **запущенном** рантайме поля `leName`, `lePort`, `spQueueSize`, `cbMode`, `cbType` **блокируются** (`_set_fields_enabled(False)`), чтобы конфиг не менялся во время работы. Кнопка `btnAddRegister` и редактирование колонки адресов **не** отключаются: можно добавлять строки и менять адреса и при работающем сервере (разумная нагрузка — нечастые правки).

## Таблица переменных (holding/coil) и опрос значений

**Синтаксис адреса** в первой колонке совпадает с `parse_register_token` (`core/controller/addresses.py`): префиксы **`D`/`d`** и **`M`/`m`**, голое число **2048…4095** — coil, иначе holding **0…10000**, coil datastore **0…5000** (подробно — [config_controllers.md](config_controllers.md#register_addresses--схема-json-и-разбор-адреса)).

- **Сохранение в JSON:** при сохранении линии с карточки в `ControllerConfig.register_addresses` попадают **строковые токены** из ячеек «Переменная» (например `"D100"`, `"2801"`, `"4146"`), а не числовые адреса datastore. Legacy-файлы с **`int`** в JSON по-прежнему открываются; пока линию не пересохраняют с карточки, в модели элементы остаются **`int`**. Колонка «Значение» в модель не входит.
- **`load_options(config)`:** очищает таблицу; для каждого элемента `register_addresses` в первую колонку — десятичный текст для **`int`** (не `bool`) или исходная **`str`**; «Значение» пустое; рантайм не стартует.
- **`options()`:** по порядку строк, пустые адреса пропускаются; непустой текст разбирается через **`parse_register_token`**, в список попадает **`parsed.token`** (введённый пользователем текст после strip). Колонка «Значение» не влияет. Ошибка разбора — **`ValueError`**: *«Строка N: недопустимый адрес переменной»* (**N** — номер строки с единицы, пустые строки в нумерации участвуют).
- **Опрос:** при **`tbRun`** и успешном `ControllerRuntime.start` — **`QTimer`** **500** мс; первый тик сразу после старта. На каждом тике (**GUI-поток**) для валидных строк накапливается список **`("holding"|"coil", address)`**, один вызов **`ControllerRuntime.read_points`** (локальный datastore — см. [controller_core.md](controller_core.md#чтение-holding-и-coil-read_points)). Отдельный Modbus-клиент из виджета **не** создаётся.
  - Пустой адрес или ошибка **`parse_register_token` на тике:** текст «Значение» очищается, **`ForegroundRole`** сбрасывается (без красного), строка **не** уходит в `read_points`.
  - Успех **`bool`:** `"True"` / `"False"`, цвет **`QColor(0, 128, 0)`**; успех **`int`:** `str(int)` (в т.ч. **`"0"`** — ячейка не пустая), тот же зелёный. Проверка **`bool` раньше `int`**. В **`Qt.ItemDataRole.UserRole`** item колонки 1 сохраняется тот же канонический текст (для отката при неверном вводе).
  - Слот **`None`** (ошибка чтения точки): текст **пустой**, **`QColor(128, 0, 0)`** (отдельная подпись «Ошибка» не выводится); **`UserRole` не меняется** — отказ пользовательского ввода может вернуть прежний успешный текст.
  - Исключение **`read_points`** или длина ответа ≠ числу точек: **DEBUG** в лог **`CTL`**, ячейки **не меняются**, UI не падает.
  - **Открытый редактор** колонки «Значение» (`QAbstractItemView.State.EditingState`, `currentIndex()` — та же строка, столбец **1**): для этой строки тик **не** вызывает `setText`, `setForeground`, сброс цвета и `setData` (ни успех, ни красная пустая, ни очистка из‑за плохого адреса). Остальные строки обновляются; `read_points` по-прежнему читает все валидные точки.
  - Все программные правки item колонки 1 (`setText`, `setForeground`, `setData` для `ForegroundRole` и `UserRole`) идут через счётчик **`_register_cell_guard`** и **`blockSignals(True)`** на таблице, чтобы слот **`itemChanged`** не вызывал **`write_point`** повторно.
- **Стоп (`run(False)`):** таймер останавливается, `runtime.stop()`, `_runtime = None`, затем очистка колонки «Значение» (текст, **`ForegroundRole`**, **`UserRole`**) и снятие **`ItemIsEditable`**; адреса в колонке «Переменная» сохраняются.

Типовые адреса очереди Doypack (Delta / Xinje) — в [controller.md](controller.md); таблица — произвольный набор holding/coil для наблюдения (в т.ч. регистры очереди **4146** / **20** — запись из UI допустима, цикл Doypack может перезаписать значение).

## Редактирование колонки «Значение» (при **S**)

Доступно только пока **`tbRun`** включён, рантайм успешно стартовал (`self._runtime is not None`): для ячеек колонки 1 выставляются флаги **`ItemIsEnabled | ItemIsSelectable | ItemIsEditable`** (после `start`, для новых строк через **`_append_register_row`** / **`_value_table_item`**). На остановленной карточке слот **`_on_register_item_changed`** выходит **без** изменения текста — произвольный текст в «Значении» не пишется в datastore и не очищается.

Сигнал **`tblRegisters.itemChanged`** подключён один раз в **`_connect_ui`**. Коммит правки колонки **1**:

1. Адрес строки — **`parse_register_token`** по тексту колонки «Переменная»; пустой или невалидный адрес — откат без **`write_point`**.
2. Текст «Значение» после **`strip`**: допускаются **только ASCII-цифры** `0-9` (без знака, точки, запятой, букв; слова **`True`** / **`False`** не принимаются).
   - **holding:** целое **0…65535** включительно (ведущие нули схлопываются: `0007` → запись **7**, отображение **`"7"`**). Вызов **`ControllerRuntime.write_point("holding", address, int)`** — см. [controller_core.md](controller_core.md#запись-holding-и-coil-write_point).
   - **coil:** целое **0** → **`False`**, любое **> 0** → **`True`**; в рантайм уходит **`bool`**, на экране **`"False"`** / **`"True"`**.
3. Успех **`write_point`:** под защитой guard — канонический текст, зелёный **`QColor(0, 128, 0)`**, обновление **`UserRole`**.
4. Мусор, holding вне **0…65535**, сбой **`write_point`** (`False` или исключение, **DEBUG** в **`CTL`** без traceback): datastore **не** меняется, **`QMessageBox` не** показывается; ячейка возвращается к последнему успешному тексту из **`UserRole`** (зелёный) или к пустой без красного, если успешного чтения ещё не было.

Колонка **0** при правке **не** откатывается слотом значения и **не** инициирует запись в datastore. **`options()`** по-прежнему сериализует **только токены** из колонки «Переменная»; введённые значения в JSON линии **не** сохраняются.

**`editTriggers`** таблицы не меняются (в т.ч. **`AnyKeyPressed`**): при **`ItemIsEditable`** клавиша открывает редактор ячейки вместо **`keyboardSearch`** по строкам.

## Кнопка `tbRun` (R / S)

Поведение как у принтерной карточки: переключатель с подписью и цветом.

- **Остановлено** (`unchecked`): текст **«R»** (Run), стиль `color: #00FF00`.
- **Запущено** (`checked`): текст **«S»** (Stop), стиль `color: #FF0000`.

Слоты: `tbRun.toggled` → `run(toggled)` и `_setup_icon(toggled)`.

### Логика `run(toggled)`

- Если **и** имя, **и** порт пустые — переключатель сбрасывается в «стоп», выход (рантайм не стартует).
- При **включении** (`toggled=True`): порт читается как `int(self.lePort.text().strip())`. При **некорректном** значении (не число) — тихий откат: `tbRun` снимается, рантайм не создаётся (**в отличие** от `options()`, см. ниже).
- Параметры для рантайма: `queue_size = spQueueSize.value()`, `duplex = (mode == duplex)`, `xinje = (type == xinje)`.
- При **успешном старте** сохраняется `self.name = leName` (после `strip`).
- При **выключении**: `ControllerRuntime.stop()`, ссылка обнуляется; поля снова доступны.

Если `runtime.start(...)` бросает исключение: запись **ERROR** в лог виджета (см. логирование), остановка попытки, сброс `tbRun`, включение полей.

## Кнопка удаления `tbDelete`

1. Если `tbRun` **включён** (сервис запущен) — **предупреждение** «Остановите виджет перед удалением», выход.
2. Иначе — диалог подтверждения с именем (`leName.strip()` или запасное `self.name`).
3. При ответе **Yes** эмитится сигнал **`delete_requested`** — фактическое удаление с холста выполняет внешний код (`MainLineField` / эмулятор линии).

## `options()` и сохранение JSON

Метод **`options() -> ControllerConfig`** собирает конфигурацию для слоя сохранения линии.

- Порт: `int(self.lePort.text().strip())`.
- При ошибке преобразования выбрасывается **`ValueError`** с текстом: *«Порт карточки контроллера должен быть целым числом»* (цепочка `from exc` для исходного `ValueError`). Это позволяет **явно** отловить неверный ввод на этапе сохранения, в отличие от молчаливого отказа в `run()`.

Остальные поля: `name`, `queue_size`, `mode`, `controller_type` — как на форме (см. таблицу выше).

**Адреса в первой колонке таблицы:** см. раздел «Таблица переменных» — при сохранении линии невалидный токен даёт **`ValueError`** *«Строка N: недопустимый адрес переменной»*; на тике опроса тот же мусор только очищает «Значение» без красного и не участвует в `read_points`.

## Рантайм и логирование

- Экземпляр **`ControllerRuntime`** (`core/controller/runtime.py`) создаётся при успешном переходе `tbRun` в «запущено» и хранится в `self._runtime`; описание потока, asyncio и порядка Modbus/Doypack — в [controller_core.md](controller_core.md) («ControllerRuntime»).
- Виджет пишет ошибки старта через **`logging.getLogger(CONTROLLER_LOGGER)`**, где **`CONTROLLER_LOGGER = 'CTL'`** (`libs/loggers.py`). В коде зафиксировано тот же согласованный подход, что и в ядре: **stdlib** `logging` с именем **`CTL`**, не `get_dmc_logger` (см. комментарий в `controller_widget.py` и раздел «Логирование (CTL)» в [controller_core.md](controller_core.md)).

## Сигнал

- **`delete_requested`** (`Signal()`) — запрос на удаление карточки после подтверждения и при остановленном рантайме.
