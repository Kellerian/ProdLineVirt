# Конфигурация контроллера линии (Modbus TCP / Doypack)

Модели: `core/controller/data.py`. Корневое поле списка: `core/main_ui/data.py` → `ConfigFile.controllers`.

## `ConfigFile.controllers`

| Поле | Тип | По умолчанию | Назначение |
|------|-----|--------------|------------|
| `controllers` | `list[ControllerConfig]` | `[]` | настройки Modbus TCP-контроллеров (карта устройств Doypack) на холсте эмулятора |

**Обратная совместимость:** если в JSON **нет ключа** `controllers` (как в файлах, сохранённых до появления раздела), при загрузке подставляется **пустой список** `[]` — валидация не падает (аналогично другим спискам в `ConfigFile`, см. `tests/test_core/test_controller_config.py`).

## Перечисления

### `ControllerMode` (`str`, Enum)

Режим линии Doypack для карты контроллера.

| Значение | Строка JSON |
|----------|-------------|
| `simplex` | `"simplex"` |
| `duplex` | `"duplex"` |

В JSON поле `mode` задаётся строкой; при строгой схеме (`ConfigDict(strict=True)`) допустимы только перечисленные значения — иначе ошибка валидации.

### `ControllerType` (`str`, Enum)

Вариант PLC / карты регистров для карты контроллера.

| Значение | Строка JSON |
|----------|-------------|
| `delta` | `"delta"` |
| `xinje` | `"xinje"` |

Поле `controller_type` в JSON — строка с одним из значений выше.

## `ControllerConfig`

Один элемент массива `controllers[]`: конфигурация Modbus TCP-контроллера на холсте.

| Поле | Тип | Обязательное | По умолчанию | Описание |
|------|-----|--------------|--------------|----------|
| `name` | `str` | да | — | Имя устройства на холсте |
| `port` | `int` | да | — | TCP-порт Modbus-сервера эмулятора |
| `queue_size` | `int` | нет | `10` | Размер очереди состояний Doypack (допустимо **1–1000** включительно) |
| `mode` | `ControllerMode` | нет | `simplex` | Режим линии (см. выше) |
| `controller_type` | `ControllerType` | нет | `delta` | Тип PLC/регистров (см. выше) |
| `register_addresses` | `list[int]` | нет | `[]` | Адреса **holding**-регистров (диапазон каждого элемента **0…10000** включительно). В JSON сохраняются **только адреса**; текущие значения регистров в модель не входят |

Ограничение **`queue_size`:** значения вне диапазона **1…1000** отклоняются валидацией (`ge=1`, `le=1000` в Pydantic). Согласовано с использованием в эмуляции (`DoypackEmulation` и тестах).

**`register_addresses` (подзадача #1, схема JSON):**

- Модель: `core/controller/data.py` → `list[RegisterAddress]` с границами **`ge=0`**, **`le=10000`** на каждый элемент; `ConfigDict(strict=True)`.
- **Обратная совместимость:** если ключ **`register_addresses` отсутствует** в объекте контроллера в JSON, при загрузке подставляется **`[]`** (как и для отсутствующего корневого `controllers`). Явный **`null`** вместо списка — ошибка валидации.
- Порядок элементов сохраняется при round-trip (`model_dump_json` → `model_validate_json`); повторяющиеся адреса допустимы.
- Строгая схема: **`bool` не принимается** за целое, строки (**в т.ч. `"4146"`**) и **`float` не приводятся** к `int`; элемент вне **0…10000** — ошибка валидации. Поведение зафиксировано в `tests/test_core/test_controller_config.py`.
- При сохранении линии в дампе JSON у новых конфигураций обычно присутствует ключ `"register_addresses"` (в т.ч. как пустой массив `[]`), даже если адреса не задавали.

## Связь с UI

Карточка контроллера (`ControllerWidget`) выводится на холсте эмулятора; сохранение и загрузка линии проходят через `options()` / `load_options()` и используют эту схему. Поле `register_addresses` — сериализуемый список адресов holding для таблицы на карточке (редактирование и опрос — [controller_widget.md](controller_widget.md)).

## Пример фрагмента JSON

```json
{
  "controllers": [
    {
      "name": "CTL_5020",
      "port": 5020,
      "queue_size": 10,
      "mode": "simplex",
      "controller_type": "delta",
      "register_addresses": [4146, 4148, 4150]
    }
  ]
}
```
