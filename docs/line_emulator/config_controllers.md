# Конфигурация контроллера линии (Modbus TCP / Doypack)

Модели: `core/controller/data.py`. Корневое поле списка: `core/main_ui/data.py` → `ConfigFile.controllers`.

## `ConfigFile.controllers`

| Поле | Тип | По умолчанию | Назначение |
|------|-----|--------------|------------|
| `controllers` | `list[ControllerConfig]` | `[]` | настройки Modbus TCP-контроллеров (карта устройств Doypack) на холсте эмулятора |

**Обратная совместимость:** если в JSON **нет ключа** `controllers` (как в файлах, сохранённых до появления раздела), при загрузке подставляется **пустой список** `[]` — валидация не падает (аналогично другим спискам в `ConfigFile`, см. `tests/test_core/test_controller_config.py`).

## Перечисления

### `ControllerMode` (`str`, Enum)

Режим линии Doypack для карты контроллера.

| Значение | Строка JSON |
|----------|-------------|
| `simplex` | `"simplex"` |
| `duplex` | `"duplex"` |

В JSON поле `mode` задаётся строкой; при строгой схеме (`ConfigDict(strict=True)`) допустимы только перечисленные значения — иначе ошибка валидации.

### `ControllerType` (`str`, Enum)

Вариант PLC / карты регистров для карты контроллера.

| Значение | Строка JSON |
|----------|-------------|
| `delta` | `"delta"` |
| `xinje` | `"xinje"` |

Поле `controller_type` в JSON — строка с одним из значений выше.

## `ControllerConfig`

Один элемент массива `controllers[]`: конфигурация Modbus TCP-контроллера на холсте.

| Поле | Тип | Обязательное | По умолчанию | Описание |
|------|-----|--------------|--------------|----------|
| `name` | `str` | да | — | Имя устройства на холсте |
| `port` | `int` | да | — | TCP-порт Modbus-сервера эмулятора |
| `queue_size` | `int` | нет | `10` | Размер очереди состояний Doypack (допустимо **1–1000** включительно) |
| `mode` | `ControllerMode` | нет | `simplex` | Режим линии (см. выше) |
| `controller_type` | `ControllerType` | нет | `delta` | Тип PLC/регистров (см. выше) |
| `register_addresses` | `list[str \| int]` | нет | `[]` | Токены наблюдаемых регистров для таблицы на карточке (holding или coil после разбора). В JSON — **только адреса/токены**; текущие значения регистров в модель не входят |

Ограничение **`queue_size`:** значения вне диапазона **1…1000** отклоняются валидацией (`ge=1`, `le=1000` в Pydantic). Согласовано с использованием в эмуляции (`DoypackEmulation` и тестах).

### `register_addresses` — схема JSON и разбор адреса

- **Модель:** `core/controller/data.py` → `register_addresses: list[str | int]`, `ConfigDict(strict=True)`; валидатор `mode="before"` нормализует каждый элемент через `normalize_register_token` (`core/controller/addresses.py`).
- **Элемент списка:** только **`str`** или **`int`** (не `bool`, не `float`). `str` — текст пользователя после `strip` (регистр префикса `D`/`M` сохраняется). `int` — **legacy**-файлы: число проверяется теми же правилами разбора и **остаётся `int`** в модели (round-trip без переписывания в строку). `4146` и `"4146"` задают один и тот же holding **4146**; `2801` и `"2801"` — coil **2801**.
- **Обратная совместимость:** если ключ **`register_addresses` отсутствует** в объекте контроллера, подставляется **`[]`**. Явный **`null`** вместо списка — ошибка валидации. Старые массивы вида `[4146, 4148, 4150]` по-прежнему валидны.
- Порядок элементов сохраняется при round-trip; **повтор одного адреса/токена допустим**. Невалидный токен или адрес вне диапазона для выбранного типа — `ValidationError` при загрузке JSON. Поведение — `tests/test_core/test_controller_config.py`.

**Допустимые диапазоны datastore** (константы в `addresses.py`, согласованы с `ModbusEmulator`):

| Тип после разбора | Диапазон адреса |
|-------------------|-----------------|
| holding | **0…10000** |
| coil | **0…5000** |

**Грамматика токена** (`parse_register_token`): пробелы по краям снимаются; пробелы внутри токена не допускаются.

| Форма | Тип | Числовой адрес | Пример |
|-------|-----|----------------|--------|
| `D`/`d` + десятичные цифры | holding | `4096 + N` | `D100` → 4196; ведущие нули ок (`D0100` → 4196) |
| `M`/`m` + десятичные цифры | coil | `2048 + N` | `M100` → 2148 |
| строка **только из цифр**, значение **2048…4095** | coil | само число | `2801`, `2567`, `2048`, `4095` |
| строка только из цифр **вне** 2048…4095 | holding | само число | `4146`, `0`, `20`, `5001`, `10000` |

Иные формы (`abc`, `X100`, голый `D`/`M`, `D100a`, `D 100`, `+4146`, пустая строка) — ошибка. **Семантика legacy:** голое число в полосе **2048…4095** трактуется как **coil** (раньше в схеме только holding такое число тоже проходило по диапазону 0…10000, но читалось как holding). Адреса очереди Doypack **`4146`**, **`20`** остаются holding.

## Связь с UI

Карточка контроллера (`ControllerWidget`) на холсте при **загрузке** линии выводит каждый элемент списка в первую колонку таблицы (`load_options`, для `int` — десятичный текст). Схема JSON и разбор токенов — здесь; ввод с карточки, `options()` и опрос значений — [controller_widget.md](controller_widget.md).

## Пример фрагмента JSON

```json
{
  "controllers": [
    {
      "name": "CTL_5020",
      "port": 5020,
      "queue_size": 10,
      "mode": "simplex",
      "controller_type": "delta",
      "register_addresses": [4146, 4148, 4150]
    }
  ]
}
```

Тот же список допустим со **строковыми** токенами (и в **смешанном** виде с legacy-`int`):

```json
"register_addresses": ["D100", "M100", "2801", "4146", 4150]
```
